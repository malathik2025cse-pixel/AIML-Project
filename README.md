# MedShield backend

## Local PostgreSQL setup

1. Create a PostgreSQL database and copy `.env.example` to `.env`.
2. Set `DATABASE_URL`, a stable random `JWT_SECRET_KEY` of at least 32 random bytes, and the comma-separated frontend origins in `CORS_ORIGINS`.
3. From this directory, install `python -m pip install -r requirements.txt`.
4. Apply the reproducible schema with `alembic upgrade head`.
5. Create the single administrator using `python create_admin.py`.
6. Optionally load synthetic UI demonstration accounts with `python seed_demo.py`.
7. Start the API with `uvicorn app.main:app --reload`.

The seed command is idempotent and is for local demonstration only. It creates ten patients, ten doctors, one administrator and one temporary consent pair. All seeded accounts use `DemoPass!2026`; never use the seed accounts in a deployed environment.

## ML review signal

Run `python train_ml.py` after installing the backend requirements. The command generates a deterministic 5,000-row synthetic tabular dataset in memory, compares Logistic Regression and Random Forest with a held-out stratified split, prints measured accuracy, precision, recall, F1 and ROC-AUC, selects by ROC-AUC then F1, and writes the selected fitted pipeline plus metrics under `app/ml_artifacts/`.

Labels are synthetic review-signal labels generated by the documented function in `train_ml.py`; they are not derived from clinical outcomes or real patient records and provide no clinical validation. The API uses the selected model only as a doctor-facing decision-support signal. SHAP values are used for Random Forest explanations when available; the explanation falls back to listing active input factors if SHAP cannot calculate a result. Patients do not receive model output.

## Tests

Install development/test dependencies with `python -m pip install -r requirements-dev.txt`, then run `python -m pytest tests -q -p no:cacheprovider`.
